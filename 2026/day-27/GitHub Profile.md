# Day 27 – GitHub Profile Makeover

## Objective

The goal of Day 27 was to transform my GitHub profile into a professional developer portfolio that clearly represents my DevOps learning, projects, skills, and hands-on experience.

---

## 1. Profile Audit

Before making changes, I reviewed my GitHub profile from a recruiter's perspective.

### Before

* Profile README was missing/not optimized.
* Repositories were not consistently organized.
* Some repositories needed better descriptions.
* Project documentation could be improved.
* Important projects were not clearly highlighted.
* Repository naming needed consistency.

---

## 2. Profile README

Created a dedicated GitHub Profile README repository using my GitHub username.

The README includes:

* Short professional introduction
* Current learning journey
* DevOps skills and tools
* Current projects
* Important repository links
* Contact/social links

The goal was to keep the README simple, professional, and focused on what I am currently building and learning.

---

## 3. Repository Organization

Organized my repositories around the main areas of my DevOps journey.

### 90 Days of DevOps

Contains my daily DevOps learning and hands-on tasks.

Topics include:

* Linux
* Git & GitHub
* Shell scripting
* AWS
* Docker
* Kubernetes
* CI/CD
* DevOps automation

### Shell Scripts

Dedicated repository for my Bash and shell scripting practice.

Examples include:

* System monitoring
* File operations
* Log analysis
* Automation scripts
* Backup scripts

### Python Scripts

Repository for Python automation and learning projects.

### DevOps Notes

Central location for:

* DevOps notes
* Cheat sheets
* Git commands
* Linux commands
* Shell scripting notes
* Interview preparation

---

## 4. Repository Documentation

For each important repository, I focused on:

* Clear repository name
* One-line description
* Proper README.md
* Organized folder structure
* Relevant `.gitignore`
* Clear project documentation

---

## 5. Pinned Repositories

Selected my most relevant projects and learning repositories for my GitHub profile.

The pinned repositories represent:

* DevOps learning
* Kubernetes
* Docker
* CI/CD
* GitHub Actions
* Shell scripting
* Cloud and automation

---

## 6. Security Check

Reviewed repositories to make sure sensitive information was not exposed.

Checked for:

* `.env` files
* API keys
* Passwords
* Access tokens
* AWS credentials
* Private configuration files

Sensitive files should be excluded using `.gitignore`.
